# Change: 019-e2e — Complete journey regression suite

Status: done (M6 gate passed 2026-09-27). Date: 2026-09-27. Scope owner: Claude. Task: MVP-19. Verification: M6 gate (ADR-0004).

## Problem and behavior

Maps ADM-A3 and the cross-domain scenarios in [testing](../../quality/testing.md). The system already had per-feature Go, contract and browser tests, but three things were missing:
- a single journey across both apps on one visit;
- a machine-checkable requirement-to-test map;
- concurrency group 4 (line cancellation racing begin-settlement).

## Decisions

- **Cross-app journey:** `src/pwa/journey/visit.spec.ts` runs with `playwright.journey.config.ts`, which starts both production builds (PWA :3000, admin :3001) against the E2E API. `make journey` runs it as a separate step in `make verify`.
  - **Steps:** manager adds a table → guest joins (phone A) → host calls and seats → phones A and B order separately → kitchen serves → phone B signs up, verifies and claims → cashier settles → payment revokes phone A → phone B sees 1 point and history → host records departure → cleaning → ready.
  - **Deterministic start:** the host first cancels leftover waiting tickets from earlier suites. Otherwise fairness (QUE-003) would correctly require a manager override to call a later party.
- **Traceability:** tests cite requirement IDs in comments. [coverage.md](coverage.md) is generated by matching every `**XXX-NNN**` requirement and `XXX-An` acceptance ID in `specs/features/*.md` against test files. It lists 81 IDs with 0 uncited; concurrency groups map to named tests.
- **Concurrency group 4:** `TestCancellationVersusBegin` runs five rounds with a barrier. Either the cancellation commits first (begin sees `BILL_VERSION_CONFLICT` with the fresh total) or begin wins (the cancellation gets `VISIT_STATE_CONFLICT` and the snapshot includes the line). Never both.
